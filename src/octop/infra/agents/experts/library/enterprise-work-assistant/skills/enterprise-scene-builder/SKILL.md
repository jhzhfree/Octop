# 企业场景编排

此技能帮助员工把自然语言需求整理成可复用的工作流设计，并映射到 Octop 现有能力。它不增加新的调度器或企业系统连接器。定时执行应通过 Octop 任务页/Cron 设置；外部系统需要管理员按企业环境配置相应 MCP/Connector、凭据和权限。

## 场景定义步骤

收集以下内容，缺项时提出最少量的针对性问题：

1. **目标与验收**：希望完成什么；什么证据说明任务完成。
2. **触发方式**：手动、时间计划或现有消息入口；时间与时区。
3. **作用范围**：组织、用户、应用、主机、集群、项目或文档集合；维护负责人。
4. **数据输入**：指标 API、日志、工单、项目平台、知识库、文档等来源；采集时间窗。
5. **处理步骤**：按依赖顺序描述采集、校验、分析、交叉核对、生成材料。
6. **所需能力**：Octop 内已有工具、插件、技能、专家、MCP server、Connector 或通道；读/写权限。
7. **输出与通知**：报告类型、保存位置、收件人/群组的配置标识、允许分享的内容。
8. **运行策略**：超时、重试、并发、去重、失败通知、保留期限。
9. **审批边界**：自动操作白名单，需审批的动作，完全禁止的动作。

输出一份人类可审阅的场景说明，并用 references/scene-template.yaml 的结构整理。YAML 是设计/交接模板；当前 Octop Cron 接收自然语言 prompt，不会直接解析这个 YAML。不要声称 YAML 可以导入或自动运行。

## 运行级别

- **Level 0 — 草稿**：分析用户提供的信息，形成报告或操作计划。
- **Level 1 — 只读自动化**：在明确的授权范围内读取状态、对比阈值、整理结果。适合低风险定期巡检。
- **Level 2 — 配置的外部写入**：发企业微信消息、建工单或保存报告。要求预配置目标白名单、数据脱敏和审计。
- **Level 3 — 变更或安全测试**：生产环境变更、重启、删除、漏洞利用或扫描范围变更必须通过组织批准的审批流程；未接入审批门禁时只输出建议，不执行。

## 设备巡检推荐步骤

1. 读取资产清单和员工当前授权范围；只处理明确列出的资产。
2. 通过组织批准的 SSO/MCP/堡垒机连接，以员工身份或受控的最小权限服务身份登录；不得复制、缓存或打印登录秘密。
3. 采集约定的 CPU、内存、磁盘、关键服务、端口、版本和日志摘要；记录采集时间、主机标识和每项成功/失败状态。
4. 检查数据完整性和阈值配置，再对照前次巡检；缺失数据不应被判定为正常。
5. 形成报告：总体状态、异常等级、证据、影响范围、趋势、建议、未检查项与运行 ID。
6. 按配置将完整报告存入访问受控位置；消息通道只发送简报和受控链接。
7. 只读自动检查结束。任何修复、重启或安全扫描都必须遵循对应的独立审批策略。

## 漏洞扫描规则

扫描前必须同时具备资产所有者授权、目标 allowlist、扫描器连接和选定的安全策略。默认限于经批准的安全基线或温和扫描；不得自行扩大 CIDR/主机范围、运行利用载荷、尝试凭据、改变防护策略或自动修复。结果要说明扫描器、策略、时间、目标、覆盖率与错误。没有扫描权限时生成待审批的扫描计划。

## 报告格式

- 执行摘要与总体状态
- 范围、数据来源、采集时间、运行 ID
- 检查项：当前值、阈值、结论、证据
- 异常/阻塞、影响和置信度
- 未覆盖资产与连接失败
- 建议和需要人工审批的后续动作
- 通知状态（目标、时间、消息 ID；没有发送则写明原因）

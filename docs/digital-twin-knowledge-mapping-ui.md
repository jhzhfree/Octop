# 知识映射管理界面（R2）

独立组件 `KnowledgeMappings` 接入组织数字员工工作区，不增加侧栏。仅对组织管理者渲染；服务端仍是授权边界。

- 读取已有岗位知识能力和当前用户可见的外部来源，必须显式选择，不按名称自动关联。
- 来源候选要求 AKB Agent 身份、启用、绑定当前 Agent、精确 KB ref、已知正整数来源/连接版本；不发任何检索或探测请求。
- 现有外部来源 API 未分页，一次读取后按名称/ID 筛选，最多显示 100 个匹配选项。映射列表使用真实 limit/offset 分页，不推断总数。
- 创建/撤销先展示确认，发送观察到的版本。409 后清除待提交数据，必须刷新和重新确认，不自动重试。员工能力版本变化时须关闭面板并刷新父页；面板刷新仅重读映射和来源。
- 列表 `local_snapshot_current=null` 显示未检查；显式单项检查后才显示本地一致/失效。二者都不代表 AKB 用户 ACL 或检索授权。
- 关闭或切换员工后，晚到响应不能覆盖新上下文。已发出的写请求不保证因关闭取消，界面明确要求重新刷新核对。
- `retrieval_enabled` 始终为 false；没有真实 AKB、模型或跨产品调用。

父页集成建议：在已选员工工作区的管理操作处添加 `<KnowledgeMappings key={selectedWorker.worker_id} organizationId={organizationId} worker={selectedWorker} canManage={canManage} />`，按父页实际变量名调整。

限制：本地候选过滤不是授权；没有满足条件的候选时需先在既有知识来源和岗位能力管理中建立绑定。用户权限或版本在请求期间变化仍由服务端拒绝。真实浏览器和外部 ACL 未验收。

# 企业工作助手场景模板

Octop 已提供多用户 Agent、专家/团队、Skill、插件、MCP/Connector、知识库、企业微信等通道以及 Cron 定时任务。本改动增加一个可安装的「企业工作助手」专家模板和场景编排 Skill，复用这些已有机制，不替换原有对话、桌面、CLI、通道或自托管功能。

## 能力映射

| 企业工作内容 | Octop 现有能力 |
| --- | --- |
| 设备巡检、故障诊断 | 企业工作助手 + 系统医生/运维专家 + 已授权的监控、日志和堡垒机 MCP/Connector |
| 定期运行和结果推送 | 专家任务样例 + 现有 Cron + 已配置的企业微信/飞书等通道 |
| 故障报告、培训 PPT | 办公自动化专家及已安装的文档/PPT 技能 |
| 进度检查 | 项目平台 Connector/MCP 或项目知识库；按配置范围读取 |
| 技术查询 | 已配置的搜索/知识库能力；优先官方资料并保留来源 |
| 漏洞扫描 | 经批准的扫描器 MCP/Connector + 明确资产 allowlist 和安全策略 |
| 多专业协作 | 现有专家团队和 Agent 间派工 |

## 当前边界

本模板是专家角色、技能说明和配置样例。Octop 当前 Cron 任务以自然语言 prompt 执行，**不会直接导入或运行 scene-template.yaml**；模板 YAML 是设计与交接格式。模板也不内置某厂商的身份系统、堡垒机、CMDB、监控、项目平台或漏洞扫描器。管理员需要按实际环境配置受支持的 MCP/Connector，并在对应系统中给员工或受控服务身份授权。

场景模板中的 `execution` 与 `policy` 字段描述目标执行契约，并不代表当前 Cron 已经强制执行幂等、互斥、审批或失败关闭。随本轮新增的单元测试只验证模板自身的安全默认值和结构，不能替代运行时授权、调度或集成测试。

要做到真正的低代码场景导入、节点编排、运行状态/重试策略和审计视图，还需要单独开发场景定义存储、版本管理、可视化编排器和执行器。这些能力没有由本模板冒充实现。

## 安装和配置

1. 在 Octop 专家库中创建或安装「企业工作助手」专家。
2. 为员工分配该专家和其可用工具。继续使用 Octop 现有用户隔离与 Agent 权限。
3. 管理员连接组织批准的 MCP/Connector：统一身份、堡垒机、监控、日志、资产台账、项目平台、报告存储和漏洞扫描器。先以只读工具进行验收。
4. 将场景模板中的资产组、指标、阈值、维护窗口、报告位置填成企业批准的配置标识；不要把密码、令牌或 MFA 验证码放进提示词。
5. 先手动运行并核对数据来源、范围、异常处理和报告内容。验证通知 allowlist 后再启用自动通知。
6. 经场景负责人审核后，在 Agent 的任务页按 task_examples 创建 Cron；检查时区、运行身份、启用状态和最近运行结果。
7. 漏洞扫描单独设置范围、策略、速率和审批。先使用安全基线/温和配置，并用测试资产验收；扫描不得自动扩大范围或自动利用漏洞。

## 建议的落地顺序

- **P0：场景定义契约和安全回归测试** — 明确版本、授权范围、身份、步骤顺序、失败策略、幂等意图和审批动作；测试模板的安全默认值。
- **P1：人工可审阅的只读场景** — 配置校验、单次执行和证据报告。
- **P2：可靠的定期任务** — 只读巡检 + 失败告警 + 报告存档；明确任务所有者、重试和凭据失效处理。
- **P3：企业写入动作与审批门禁** — 通知、工单、知识沉淀；按收件人 allowlist、脱敏和审计逐项开放。
- **P4：可视化场景编排** — 把 YAML 结构升级为版本化 API、表单编辑器、步骤执行状态和回放审计。
- **P5：受控变更自动化** — 只在企业身份、堡垒机审批、变更单和回滚验证集成完成后，考虑受限修复。

任何阶段都不应将“无人工参与”理解成绕过权限、审批和变更管理。可无人值守的是授权范围内的读取、分析、报告和已配置通知；生产变更与高影响安全操作应由企业策略决定是否要求审批。

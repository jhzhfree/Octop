## 1. 文档目的与状态口径

本文将 Octop 当前代码和仓库文档中的产品能力整理为可评审、可开发和可验收的功能要求。本文是现状规格基线，不替代 API、CLI、部署和安全操作手册。

功能状态统一使用以下口径：

| 状态 | 含义 |
| --- | --- |
| 已实现 | 当前产品/API/CLI 已提供该能力；仍需按具体部署验证配置与依赖 |
| 需配置 | Octop 提供集成入口，但需管理员配置模型、凭据、外部服务或授权 |
| Beta | 能力可用但仍处于 Beta 或内部验证阶段，不作为稳定 GA 承诺 |

本文中的“应”表示本版本可验收要求；“可”表示可选能力或实现方式。外部系统能力、企业策略和未配置的第三方服务不视为 Octop 自身交付能力。

## 2. 产品概述

Octop 是一个自托管、多用户、多 Agent 的 AI 助手平台。系统以单个 Python 服务进程组合 FastAPI 后端、React Web 控制台、CLI、Agent 运行时、消息通道和定时任务；控制面默认使用 SQLite，也支持 PostgreSQL。Agent 的工作区文件通过可插拔工作区后端管理。

产品为个人、小团队和具备自托管要求的组织提供统一入口，用于配置 AI 模型、创建专业 Agent、进行对话、接入外部工具、组织知识和文件、从消息通道调用 Agent，以及在组织结构下管理经审批的企业场景单次运行。

Octop 的运行需要一个可访问的 LLM 服务或本地模型；连接器、消息平台、对象存储和其他外部能力按需配置。除已配置的外部依赖外，产品不要求单独部署消息队列。

## 3. 目标用户与角色

| 角色 | 主要职责 | 典型权限边界 |
| --- | --- | --- |
| 系统管理员 | 初始化实例、管理用户和系统级配置、排查运行状态 | 可管理系统级资源；仍受外部系统自身授权约束 |
| 普通用户 | 使用获授权的 Agent、会话、知识库和集成 | 只能访问本人拥有或明确共享给本人的资源 |
| Agent/专家所有者 | 配置 Agent、工作区、模型、工具、通道和任务 | 仅管理本人拥有或管理员授权的 Agent |
| 组织所有者 | 维护组织、成员和组织级管理职责 | 管理所属组织，不因此自动获得成员 Agent 的工具权限 |
| 组织经理 | 管理组织结构、岗位任命、场景定义及运行审批 | 受组织角色和 Agent/Connector 授权双重限制 |
| 组织成员/场景申请人 | 查看组织场景、申请本人有权使用的 Agent 执行任务 | 组织成员身份本身不授予 Agent 访问权；不能审批自己的运行申请 |

系统管理员身份与组织角色是不同的授权层。部门、岗位职责、能力标签和任命关系用于组织建模，不自动提升 Agent 权限，也不授予凭据或工具访问权。

## 4. 产品范围

### 4.1 本版范围

- 实例初始化、身份认证、用户和权限管理。
- Agent 创建与管理、模型供应商配置、会话对话及历史记录。
- Web 控制台、CLI、桌面客户端、HTTP/WebSocket API 和已支持的 IM 通道。
- Agent 工作区、技能、专家模板、子智能体、记忆、知识库和插件能力。
- Connector/MCP、ACP 等外部工具和 Agent 协作入口。
- Cron 定时任务、管理配置、备份、可观测性与安全设置。
- 组织、部门、岗位、成员和 Agent 任命，以及版本化企业场景、人工审批、单次执行、运行历史和受限结果证据。

### 4.2 不纳入本版交付承诺

- YAML 场景模板直接导入/执行、可视化多步骤流程图、步骤级重试和补偿。
- 企业场景的周期性调度、自动扩大资产范围、自动修复或自动漏洞利用。
- 对 MCP Connector 内部单个工具实施通用的细粒度只读/写入策略；当前场景审批授权的是整条任务提示和 Connector 名单。
- Octop 自带的企业身份目录、堡垒机、CMDB、监控、项目管理、漏洞扫描或工单系统；需对接外部服务。
- 规划中的移动端 GA、自进化技能、托管 Agent、项目空间、插件市场和云边端任务调度。

## 6. 关键业务流程

### 6.1 新实例启用

1. 管理员安装/启动 Octop，进入初始化向导。
2. 管理员配置实例基础信息和控制面数据库，并创建管理员账号。
3. 管理员添加至少一个模型供应商/模型，或连接本地模型服务。
4. 管理员创建用户并授予必要角色；用户登录后创建/选择 Agent。
5. 管理员按需配置连接器、通道、存储后端和备份策略。
6. 用户通过 Web、CLI 或已配置通道开始使用 Agent。

### 6.2 企业场景运行

1. 组织所有者创建组织并维护成员、部门和岗位。
2. 有权管理员将可访问的 Agent 任命到岗位；此操作不增加工具授权。
3. 组织经理创建场景，指定岗位、Agent、提示词和精确 MCP Connector 名单。
4. 成员查看场景并申请运行；系统保存不可变申请快照，状态为 `awaiting_approval`。
5. 非申请人的组织所有者/经理审批或拒绝。审批时重新检查 Agent/岗位/Connector 授权。
6. 通过审批的任务作为一次性 Cron 执行；运行状态与 Cron 结果同步。
7. 成员可查运行记录；仅申请人、审批人或管理员可查看受限的最终答案证据。

## 7. 权限与数据边界

1. **用户边界：** 默认只访问本人资源；共享/管理员授权应由服务端在每次请求校验。
2. **Agent 边界：** 组织岗位、职责、成员身份不替代 Agent 所有权/共享授权。
3. **Connector 边界：** 外部工具按用户授权与 Agent 配置控制；企业场景运行使用申请快照中的精确 Connector 名单并重新校验申请者授权。
4. **审批边界：** 场景申请人与审批人必须不同；审批覆盖完整提示和 Connector 名单，而非 Connector 内单个工具。
5. **证据边界：** 场景证据仅向运行申请人、审批人和系统管理员开放；仅暴露可见助手文本，不暴露工具调用载荷及模型推理。
6. **凭据边界：** 令牌、密码和外部服务密钥应使用密钥/凭据管理路径，不应嵌入提示词、用户可见日志或审计负载。
7. **网络边界：** Octop 可连接管理员明确配置的 LLM、Connector、消息平台、模型下载/更新等必要外部服务；部署方应以最小出站范围配置 DNS、代理、防火墙和 TLS。未配置网络依赖的本地模型/离线能力应单独验收。

## 8. 非功能要求与交付验收

下列为本版交付质量要求。性能容量、SLA、并发用户数、响应时限和数据保留期限需由具体部署规格另行给出，不从代码推定数值。

| 类别 | 要求 | 验收证据 |
| --- | --- | --- |
| 安全 | 认证、资源权限、组织角色、Agent/Connector 授权和审批边界在服务端强制执行。 | 单元/集成权限测试及越权负向用例。 |
| 隔离 | 用户、Agent、组织、会话和场景运行快照不可互相串读。 | 多用户测试、运行会话隔离测试及证据访问测试。 |
| 一致性 | SQLite 与 PostgreSQL schema 迁移成对维护；场景更新采用版本冲突检测。 | 两类数据库迁移/仓储测试；并发过期更新返回冲突。 |
| 可审计 | 关键组织场景操作有审计动作，运行版本及审批结果可追溯。 | 审计记录核对和运行历史验收。 |
| 可维护 | API/CLI/架构/部署文档与已交付行为一致；未实现能力明确列为限制或规划。 | 文档评审、接口契约测试、交付清单。 |
| 可部署 | 可按目标环境安装、初始化、配置模型并完成一轮端到端对话。 | 在目标操作系统/容器及数据库组合上的安装部署记录。 |
| 可恢复 | 管理员可按部署手册备份并恢复控制面数据和必要工作区/文件数据。 | 恢复演练记录；仅备份数据库不视为完整恢复。 |
| 兼容 | Web 控制台、CLI、API 与已声明支持的桌面/消息入口在授权规则上保持一致。 | 各入口最小端到端测试矩阵。 |

建议提交/发布前至少执行仓库质量门禁 `make all`；场景改动还应执行相关单元测试和 API 集成测试。正式企业交付应另提供测试报告、环境规格、配置基线、备份恢复记录及未关闭问题清单。

## 10. 发布前验收清单

- [ ] 初始化、管理员登录、普通用户登录、用户管理和越权拒绝通过。
- [ ] 配置一个目标模型并完成一次 Web 对话；验证会话历史和显式取消。
- [ ] Agent 所有权、共享、工作区、知识库和 Connector 授权分别验证隔离。
- [ ] 至少验证一个计划交付的 CLI/API/桌面/IM 入口；未验证入口不得列入本次交付范围。
- [ ] Cron 启停和一次任务执行通过；消息投递仅在对应通道配置完成后验收。
- [ ] 组织成员/经理角色、岗位 Agent 任命与权限不自动扩大的约束通过。
- [ ] 企业场景版本更新、过期版本冲突、运行申请、禁止自批、拒绝、批准、授权撤销失败关闭、Cron 状态同步和证据访问控制通过。
- [ ] SQLite 或目标 PostgreSQL 迁移、备份及恢复演练通过。
- [ ] `make all` 通过；记录有意跳过项及原因，不以文档检查替代功能测试。
- [ ] 交付资料包含部署拓扑/配置、依赖清单、测试结果、安全边界、已知限制和回滚/恢复步骤。

## 11. 已知限制与后续版本建议

本版本企业场景一次执行由现有 CronManager 承载，支持单 Agent、单提示词和人工审批。当前状态可在查询时从关联 Cron 最近一次结果同步；自动恢复中断中的运行、周期性场景、步骤级状态、通用重试/补偿和场景执行器尚未实现。批准授权范围是整个提示词与 Connector 白名单；对所选 MCP 服务内部的读写工具不做通用细粒度授权，因此应优先使用只读 Connector 和受限 Agent。

建议后续按风险递增推进：

1. **场景运行可靠性：** 稳定的运行状态机、重复请求幂等、执行超时和中断恢复。
2. **受控周期任务：** 明确运行身份、维护窗口、重试/失败策略和通知白名单。
3. **细粒度审批与审计：** 步骤级工具授权、高风险动作审批、证据链和可追溯报告。
4. **流程编排：** 版本化多步骤定义、节点状态、依赖关系、回放及失败补偿。
5. **企业交付增强：** 目录服务选择器、管理员审计视图、容量/SLA 基线与运维自动化。

上述项目在完成设计、实现和测试前均属于后续建议，不构成本版验收项。

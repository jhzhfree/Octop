# 可选服务端绝对会话时限

2026-11-16，开发基线 `92a7c5b87faeee009f6e08045426a08c0606b5ca`。

## 行为与兼容策略

配置 `session_absolute_timeout_seconds` 或环境变量
`OCTOP_SESSION_ABSOLUTE_TIMEOUT`，单位秒，负数拒绝启动；0 默认关闭，保持现有
用户登录和续期策略。显式正数开启后，所有经过统一 JWT 认证的新请求都检查
签名的 `session_started_at`，达到起始时间加上限时返回 TOKEN_EXPIRED / 401。
普通 API、权限轮询和显式续期均受约束，频繁续期不能推迟该边界。

所有新的签发入口使用共享签发器写入服务器当前时间；续期保留原起始时间与 sid。
客户端自报的活动头或请求时间不参与判定。缺少起始时间、类型异常、晚于 iat 或
服务器当前时间的起始值均在启用时拒绝认证。旧格式家族在关闭策略时仍可续期，
但不会虚构一个新的原始登录时间；启用后必须重新登录。既有撤销数据库检查与
账号禁用检查保留，存储故障仍拒绝认证，不以令牌有效为由降级放行。

候选部署策略（尚未选择或应用）：8 小时适合需要每工作日重新登录的管理场景；
24 小时减少重新登录频率，但被盗凭据的可用窗口更长。默认 0 仅为本阶段向后
兼容，不是企业安全推荐值。改变部署配置需正常重启并在全部认证实例一致应用；
收紧会影响已有带起始时间的家族，放宽/关闭可能让尚未过 exp、未撤销的令牌再次
可用。不要用切换此策略替代退出撤销或应急密钥轮换。

## 精确边界

这是请求认证时的服务端绝对时限，不是 idle 时限、真人活动检测或全部令牌撤销。
现有 access-token TTL 仍单独生效；JWT exp 可以晚于绝对边界，服务端仍拒绝。
已通过认证的在途请求、已建立的流和 WebSocket 不会被计时器主动取消。时钟必须
可信；回拨可能延长实际墙钟期限。本阶段没有数据库会话表、清理迁移或新后台任务。
多进程使用一致配置及密钥可检查同一签名起始时间，但未进行真实多节点部署验收。

未改动恢复入口，原地/在线恢复继续关闭；完整安全恢复激活、ACL 映射、工作区与
数据库一致性回滚仍阻塞 1.0。Mattermost、模型、AKB 真实联调没有因本轮模拟通过
而变成可用。默认关闭的绝对时限也不代表生产安全策略已完成。

# 可选凭据空闲期限

2026-11-16，开发基线 `5b322a6c15ebfd1fcb0f180b74f4819b508accfa`。

## 本阶段交付

`session_idle_timeout_seconds` / `OCTOP_SESSION_IDLE_TIMEOUT` 默认 0，保持原来
登录和显式续期行为。启用值至少 120 秒，给现有浏览器最多 60 秒活动节流和 10 秒
请求超时留出空间；这不是可用性保证。候选企业策略为 1800 秒（30 分钟），尚未
作为生产默认值批准或应用。过短期限会增加重登录，过长期限增加遗失凭据窗口。

统一 JWT 认证在签名验证后校验整数 `iat`，到 `iat + idle` 时拒绝凭据，返回
TOKEN_EXPIRED / 401。普通 API、后台权限轮询和自报活动头不更新它。启用时，
每个通过既有账号限流、撤销及禁用校验的显式 `/auth/renew` 都签发当前服务器
时间的新凭据，即便 JWT TTL 尚未进入原有续期窗口；保留原 sid 与绝对起始时间。
关闭时保留原 TTL 阈值和 fresh-token no-op。绝对时限、JWT exp 与空闲期限取
实际最先触发的限制，过期凭据不能靠调用续期端点恢复。

它是**凭据级**空闲期限，不是共享会话家族的 last_activity 数据库。另一个标签
续期不会让旧令牌重新有效；同一时刻并发续期均携带真实签发时间和原始绝对起点。
晚到的旧令牌仍按旧时间到期，不会修改新令牌的时钟。没有新增数据库迁移或活动
写入竞争；现有撤销 tombstone 和账号续期限流仍适用。持有有效令牌的自定义客户端
仍能周期性调用显式续期，它不是人体活动证据；需要同时配置绝对时限限制最长寿命。

## 升级与部署边界

- 配置需要正常重启并在认证实例间一致应用。默认关闭不改变旧客户端；启用后不
  调用显式续期的旧客户端即便持续做普通工作也会在期限到达后要求重新登录。
- 既有令牌的已签名 iat 可作为最近签发事实，无需伪造迁移时间。缺失/非整数/
  非法时间拒绝；启用时已超期的令牌需要重新登录。收紧立即影响后续认证检查；
  放宽或关闭可能重新接受尚未过 exp 且未撤销的令牌，不能替代应急撤销。
- 请求认证以服务器时钟为准，要求时钟可信。长连接、已授权在途操作不会由计时器
  取消；客户端内容清理仍受已有权限监测与浏览器调度影响，不宣称实时清屏。
- 原有浏览器显式活动实现可接收新令牌，仍存在已记录的跨标签存储非原子限制。
  未做真实浏览器多标签、多节点或断电部署验收。

本阶段复核绝对时限：统一认证及显式续期均检查原始签名起始时间，续期不重置；
启用后缺少原始起点的旧家族拒绝。其默认关闭和部署限制保持不变。上一阶段推送
后的远端读取故障已恢复，本阶段开始 fetch 验证基线与远端一致。

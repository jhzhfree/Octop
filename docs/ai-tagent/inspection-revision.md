# 要求修改后的巡检修订与再次验收

2026-11-16，开发基线 `adb042c41bcd08c23604b75a22549f2835096752`。

## 交付行为与操作路径

此前申请人可以读取修改意见，但需要自行寻找目标、重建方案和运行入口。本轮在
组织运行详情的“要求修改”交付中增加“修订并重新申请 HTTP 巡检”。它使用原运行
固化的方案快照，创建独立草稿；原方案、原报告和不可覆盖的验收决定均保留。

1. 申请人在组织运行待办选择“要求修改”并刷新，打开原运行，进入修订向导。
   后续[待办详情审批入口](queue-run-approval.md)已增加“刷新当前运行状态”，可在当前详情内刷新；无需关闭重找。
2. 向导读取当前运行和验收意见，确认成功的 HTTP 巡检、原申请人及仍启用的员工和
   目标。修改标题、说明和步骤，明确点击“保存为新草稿”。
3. 核对新方案 ID，明确点击“将新草稿标记就绪”。该操作使用方案版本条件更新。
4. 重新启用单次 HTTP 巡检，选择当前账号拥有的来源任务，并重新确认共享；不会
   复制旧共享同意。点击“为新巡检申请独立审批”，取得新的待审批 run ID。
5. 独立审批人从待办批准新运行，系统再次采集生成新报告；独立验收人检查后提交
   新验收。原“要求修改”意见仍可查看。目标不会因此自动完成。

方案说明和步骤是此次 HTTP 流程的描述，不会被解释为修复命令；实际采集仍由所选
既有 HTTP 任务决定。需要改变端点/任务时，应先在企业助手调整获授权的任务。
其他 Agent 执行模式仍使用原有入口。本向导不调用模型、不启用记忆、不发送通知。

## 权限、并发及失败边界

未新增后端写入口或数据库迁移，所有写入使用既有组织、方案、运行接口与服务端
权限/版本/独立审批检查。原申请人检查是向导入口限制，不是新增的服务端修订权限
策略；有权限的组织管理者仍可按原接口创建方案。未新增持久化的父子修订关系，
不能据此宣称跨运行修订谱系完整可审计。

每一步只执行一次明确操作，不自动串联后续写入。双击被串行保护；结果不确定时
停止继续操作，提示先核对目标方案和运行列表，避免自动重试造成重复创建。已保存
方案可从原有目标方案入口继续。关闭、切换上下文和权限失效会清理向导；迟到响应
不回填，关闭不能取消已提交服务端写入。源目标在读取后变化仍由后端写入检查裁决。

## 企业场景及 1.0 剩余

原始目标包含数字员工使用自己的身份，经堡垒机提供的 MCP 或其他获授权接口访问
目标机器，在授权范围执行巡检，并将身份、操作及证据关联报告。未指定厂商，也不
强制 MCP。本轮只是单次 HTTP 流程的修订闭环，未验证数字员工独立机器身份、
堡垒机授权/凭据托管/目标命令/证据真实性；真实机器未连接。需在单独授权环境准备
测试身份、最小权限目标、接口及审计证据后验收。模型、AKB 和 Mattermost 真实
联调未完成，Mattermost 仍为本地预览/审批。恢复激活保持关闭；不构成 1.0 发布验收。

# 同次运行 HTTP 巡检基础版

## 可交付范围

数字员工场景选择“本次 HTTP 巡检”，从申请人自己 Agent 的 HTTP 巡检任务选取 1–10 个不同来源，明确同意向独立验收人分享结果，关闭记忆读取/写入，再经独立审批。批准范围固定任务与连接版本。后台在同一 scene_run 中创建独立子运行，只读取这些子运行实际持久结果，不使用 latest 或历史报告替代。确定性报告在本地保存并写入该场景转录，独立验收验证报告正文和 SHA-256 绑定。

普通场景模型执行和历史手动附件保留。新模式不加载模型、MCP、AKB、记忆或外发通道，不要求配置企业微信。本版不是自主数字企业，也不是周期场景调度；每次仍须显式申请/审批。已有单独巡检任务配置也不会自动授权场景分享。

## 安全和边界

- claim 及报告发布事务核验当前主体、成员资格、tasks 权限、Agent 所有权/启用状态、功能开关、员工/目标状态、岗位任职、版本及场景/Cron 绑定；SQLite 使用写事务，PostgreSQL 分支使用行锁。
- 每源调用前复核当前用户、组织成员、Agent、功能权限、资源版本、连接与 HTTP 白名单。岗位/目标状态在 claim 和最终发布核验，不保证中途撤任立即阻止后续 HTTP 读取；撤任后禁止发布。
- HTTP 采集使用现有校验适配器，首版不支持 SSH。采集数据只进入确定性格式化，不作为模型指令。实际连接仅应配置经授权的只读测试/企业端点。
- 请求人对自己的 Agent 权限是必要条件；不借 reviewer/admin 身份访问别人连接。审批摘要显示名称、ID、版本，不披露 URL/凭据。报告依现有独立验收访问控制查看。
- 同一运行只能 claim 一次；旧后台 worker 排除这些子任务。中断不自动重采集；reconciler 对丢失/error/超时场景清理未完成批次，须新建申请并重新批准。超时标失败不意味着已发出的网络读取可撤回。
- 数据库报告保存后，转录投影仍可能失败，此时保留已存报告但场景失败，不声称交付成功。

## 计数定义

`attempted` 是适配器调用前已持久的 `collection_started` 意图数，不保证已发出或完成网络请求。`succeeded` 是子运行成功持久数，不是设备健康数；`failed` 包括错误/中断终结；`unknown` 为中断前 running 的结果不确定数（failed 的子集）；`not_started` 没有派发意图。`health_unknown` 仅成功生成报告时统计健康判断未知。

`reports_persisted` 是实际批次报告数；`scene_bound` 仅表示报告 hash 与场景绑定，不等于转录投影或最终验收成功。所有来源采集失败仍可生成如实标注不可用的报告；必须结合失败数及正文验收，不得将报告存在视为来源健康。

## 验证与部署

新增真实 SQLite/仓库/HTTP 路由/审批/Cron/转录/验收链测试，HTTP 使用受控 MockTransport，模型调用断言为零。覆盖配置变化、最终撤权、岗位变化、重复投递、零成功、篡改、报告写入失败、模拟中断持久状态及 35→36 迁移。模拟中断不是实际进程重启测试。

迁移 036 提供 SQLite 和 PostgreSQL 文件。PostgreSQL 运行/并发锁、真实 HTTP 企业连接、浏览器操作、部署进程重启均未在此轮实际验证，不得宣传为真实外部联调或完整生产认证。上线前备份数据库，使用自有隔离测试端点完成申请→审批→运行→计数→独立验收；验证普通场景保持可用。新增功能受现有 enterprise_assistant 开关限制，未替用户启用外网或生产配置。

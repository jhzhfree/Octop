# 从失败巡检重新申请

适用于组织待办中的失败 HTTP 巡检。此阶段复用方案、来源选择、运行申请和独立审批接口，不增加后台自动重试或恢复激活。

## 操作路径

1. 在组织待办选择失败类别并打开运行详情，原申请人点击“从失败记录重新申请 HTTP 巡检”。
2. 系统重新读取原运行快照及当前数字员工、目标；仅失败 HTTP 巡检且员工和目标仍有效时显示编辑表单。权限以各次服务端请求为准。
3. 检查并修复来源任务和权限，修改方案说明，明确创建独立草稿，再标记就绪。
4. 重新选择当前可用来源并确认结果共享。旧来源选择和共享勾选不自动继承，记忆读写关闭。
5. 提交新申请后点击“打开新的运行申请”，在同组织查看新运行；由另一名具有权限的审批者审阅并批准。
6. 运行完成后刷新详情，读取同 run 的报告并独立验收。要求修改后的修订向导也支持直接打开新申请。

旧运行、失败状态及旧验收决定不修改。旧失败运行可能已经完成部分采集，重新申请可能再次采集；此入口不会自动重跑。关闭表单不会取消已提交的保存，请在结果不确定时先查看方案和运行列表，避免重复申请。

## 权限与审计边界

原申请人限制用于此向导；不是新增服务端权限，其他合法管理者仍可使用原有创建方案能力。
后端继续逐请求校验组织权限、方案版本、目标和来源状态，审批禁止自批。使用既有方案和申请审计；没有新增可查询的父子运行关联或声称审计记录包含返修血缘。
失败记录没有验收报告时不会请求或伪造验收意见。非 HTTP 巡检、跨组织响应、其他申请人或失效目标均不能通过此向导。

## 验证边界

前端 jsdom 验证显式操作、当前来源和重新共享、失败入口、身份与响应错配及新申请跳转回调。
临时 SQLite + ASGI 用例经公开 API 创建组织、员工、目标及来源，修改来源版本使首次运行失败，再创建新方案、独立审批、生成报告并验收；旧运行保持失败。HTTP 响应为 MockTransport 合成数据，网络与模型调用被禁止。
这些不是浏览器连接真实后端的联合验收，也不代表真实堡垒机、独立员工身份、模型、AKB 或 Mattermost 已联调。
安全沙箱浏览器尚不可用；解除条件是提供支持浏览器沙箱的隔离测试环境，不采用关闭沙箱的方式。

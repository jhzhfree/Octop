# 续期响应与登录代次绑定

2026-11-15，开发基线 `8e6660c5869da10157ab6977db1902d2c5ab709c`。

之前公共 401/503 请求已检查登录代次，但活动续期仍仅比较令牌文本。因此同标签
退出后以相同令牌重新登录，旧续期响应仍可能写入新登录；同一个活动控制器的旧
Retry-After 等待也可能延续到后续账号。

当前复用浏览器内存中的登录代次，捕获只读的令牌/代次快照。续期令牌写回、正常
检查间隔及 429 等待时间，均必须属于当前快照；相同令牌文本但不同登录代次也拒绝。
这是前端内部接口变化，不是新增服务端身份声明或鉴权依据。

新的可信用户活动发现会话已改变时，取消旧请求并清除旧等待状态，再按新登录发起
请求。登录本身不自动续期；没有新增后台定时器、重试或心跳。清除本地旧等待不重置服务端同账号的限流额度。旧请求的 finally
只允许清理自身控制器，不能取消替代请求。由本控制器正常续期引起的令牌更新会
更新其观察快照并保留已学习的服务器间隔，避免每次令牌变化都绕过节流。

## 仍未解决的边界

代次仅在当前标签内存维护。跨标签只能观察令牌文本变化，localStorage 检查与写入
不是原子 CAS；跨标签令牌变更后又变回原值（ABA）仍不保证可检测。读取存储失败、
真实浏览器冻结/恢复及多标签交互仍需独立验收。客户端快照不能证明真实人为活动，
服务端鉴权、撤销与账号级准入仍是权限边界。

本轮不改变会话空闲/绝对期限默认值，不开放恢复激活；未运行全量 make all、testmon、
受限遥测、真实模型/AKB/Mattermost、生产或部署。Docker/bubblewrap 未复测，未安装
依赖或修改安全/网络设置。尚未达到 1.0。

# 岗位目标交接（2026-11-16）

本阶段补齐负责人将一个岗位的工作交给另一岗位时缺失的正式来源与理由记录。
它创建原有 `digital_worker_goals` 草稿，继续走已有规划、审批、运行、报告与独立验收流程；
不复制权限，不启动 Agent，不发送通知，不证明自主多智能体或真实堡垒机可用。

## 操作路径

1. 在同一组织配置两个不同岗位、已任命 Agent 的活跃数字员工。
2. 管理员或组织 owner/manager 打开源员工的活跃或已完成目标，点击「岗位交接」。
3. 选择接收员工，填写交接理由、接收目标标题和验收标准，明确确认创建草稿。
4. 记录显示来源快照、接收岗位与员工、认证发起账号和目标 ID。账号认证不等于证明操作一定由真人完成。
5. 点击「打开接收员工的目标与计划」，在该员工目标列表确认对应目标，按原流程激活、规划、请求执行与审批。
6. 在组织待办按接收员工筛选，查看运行结果、报告和人工验收；组织「交接记录」可重新查找来源和接收目标当前状态。

源目标状态不变；版本递增阻止旧页面继续覆盖。接收草稿不是接收人已批准，也不是运行成功。
记录当前状态是查询时的数据库状态，并非推送或实时结果。目标列表入口不是自动跳入某个计划。

## 权限、并发与失败

- 服务端在 SQLite `BEGIN IMMEDIATE` 事务内重新检查账号启用、组织管理权限、目标组织归属、
  两端员工状态、接收岗位任命、接收 Agent 可访问性以及源目标/接收员工版本。
- 请求键按组织和认证账号隔离。相同键与相同内容重试返回原记录；改变内容返回 409。
  不同键争抢同一源版本只有一个成功。源版本更新、接收草稿、交接快照与审计同事务提交。
- 网络异常后界面冻结原请求，重试使用同一键；关闭/刷新页面后先查记录，避免人为重新发起重复业务。
  请求键不跨浏览器刷新持久化，不承诺跨刷新自动去重。
- 查询与重试均重新校验组织管理权限；撤权后的界面沿用统一访问检测边界清理。
  迟到响应不能重新显示已关闭/销毁会话；不保证远程撤权实时清屏。
- 接收员工列表只是候选，最终访问权限由服务端确认。交接不会授予执行、工具、知识库或跨组织权限。
- 保留原有草稿删除功能。删除目标或员工后交接快照仍可在组织历史查询，当前目标显示已移除；
  删除组织会按原有组织生命周期级联删除这些记录，不是独立不可删除审计存储。

## 升级与部署边界

Schema 050 新增交接表及索引，不改历史目标内容；SQLite 脚本纳入逐脚本事务迁移。
提供 PostgreSQL 对应结构脚本，但创建接口明确返回 503：尚未验证等价跨连接授权/版本锁策略。
不要混跑旧版本，也不要直接降低 schema；本阶段没有自动降级或全库回滚功能。

真实运行仍需要有权限的模型、工具、知识库和堡垒机适配等条件。在线/原地恢复及恢复激活仍关闭，
Mattermost 真实接收/执行与外发没有因本功能开放。此阶段不是 1.0 发布验收完成。

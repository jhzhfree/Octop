# 从组织待办完成同一次运行的审批

本阶段补齐“待审批待办能打开运行，但没有审批入口”的用户断点。
复用现有 `sceneRun`、`decideSceneRun` 和 `runQueue` 接口；原场景运行列表入口保留，
没有新增写接口、权限策略或数据库迁移。

## 用户操作路径

1. 有管理权限的用户进入组织运行待办，选择“待审批”，刷新并打开指定 run。
2. 点击“审阅本次运行申请”，读取当前服务端记录。界面展示申请人、固化执行说明、
   员工/目标/成功标准/方案/步骤，以及申请时的 HTTP 来源版本、共享选择和 MCP 范围。
3. 填写说明，选择批准或拒绝，再明确点击“确认决定”。批准可能启动既有执行流程，
   这一步不是验收未来报告。选择可取消；申请人不能自批或自拒。
4. 确认成功后清除旧待审批列表和审阅内容，仍在同一运行详情查看状态。
   若仍排队，点击“刷新当前运行状态”核对已存在的执行记录；不会重新执行或重试。
5. 成功后直接使用该 run 的报告、独立验收和已有 Mattermost 本地预览入口。
   验收后也可在详情内刷新，再进入修改反馈对应的修订入口，无需关闭再重新找运行。

旧的无完整方案申请仍可拒绝，批准按钮关闭；需使用就绪方案重新提交。
已经被他人处理的申请只显示现状，不再提供决定按钮。没有新增审批 TTL 或“自动过期”策略；
来源配置变化、撤权与已处理冲突由现有服务端流程裁决。来源版本变化的隔离回归验证执行失败且不采集，
不能把所有旧申请都描述为在批准前自动过期。

## 权限、并发与回退

组织管理入口和当前用户上下文决定界面可见性，服务端继续检查真实 JWT 身份、组织角色、
请求人独立性、目标范围与执行资源。仅有界面按钮或客户端传值不授予权限。
请求按 organization/run 校验响应；读到其它运行或组织的数据时不显示其内容。

两步确认、busy 防重入和服务端原有并发决定保护共同避免双击重复审批。
401/403/409/网络失败或响应不匹配会清除快照和待确认选择，不自动重试写入。
用户应先刷新现状再重新审阅；结果不确定时不能假定审批未提交。
关闭审阅、切换组织/run/用户、权限会话失效或卸载会丢弃迟到响应；关闭不会取消已提交操作。
这是界面生命周期保护，不宣称浏览器冻结时能实时收到撤权。

首次打开详情只读待办元数据；手动刷新或成功决定后的刷新会调用既有运行读取接口，
将已存在 Cron 的结果同步到运行状态，再读取待办详情。没有定时轮询，没有新执行调用。
刷新开始即销毁旧审阅/证据内容；读取失败保留错误提示，允许用户明确再次刷新。

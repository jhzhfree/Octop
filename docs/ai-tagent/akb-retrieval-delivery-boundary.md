# AKB 检索结果交付边界复核

2026-11-16；基线 5b62cf8e7298749bd015b75b3524a500662e3a97。

## 当前实际路径

- 外部来源连接和资源由 ExternalKnowledgeService 管理，连接含认证模式、endpoint、连接 revision，资源含 KB ref、resource_revision；秘密通过加密存储读取。此次仅检查代码和合成配置，未读取部署凭据。
- AKB REST 适配器请求 POST /api/v1/external/kb/retrievals，以 knowledgeBaseId 选择来源；MCP 使用既有适配器。服务认证分支清除用户 assertion，不能把它宣传成当前用户委托授权。
- Agent 认证走本仓库 Python identity SDK，依赖显式 Agent 绑定、受保护签名密钥和 AKB 的注册/授权；签名成功不证明当前用户的内容 ACL。
- 岗位 knowledge-sources 约束场景可用 MCP 工具和 KB 选择。独立 worker_knowledge_source_mappings 目前仍为不可激活草稿；知识辅助规划没有通过用户与 Agent 权限交集门槛，不得自动启用。
- 确定性 HTTP 巡检报告来自巡检来源响应，并不自动检索 AKB。此次没有给报告补造 AKB 引用或将知识映射草稿接入运行。

## 本轮修复

此前外部检索只在发请求前检查来源，等待期间配置被撤销或替换，旧响应仍可能交付。现在服务和 Agent 检索返回后、记录成功前重新读取来源和连接快照，变化或删除即拒绝。多来源融合也在交付前重查已完成来源，剔除等待其他来源期间失效的片段，返回带 source_id 的失败警告；仍有效的来源保持原 partial 行为。

校验包含持久化的连接/资源版本和配置、共享/启用状态。不会自动重试、换身份、扩大检索或退回共享管理员凭据。既有诊断记录不属于配置快照，不会因记录检查时间而误判变更。

这不是跨进程原子撤权或主动推送保证：最终数据库检查与交付仍有时间窗口，已发给上游的数据无法撤回。关联 connector 的独立凭据变更、用户会话撤销、Agent 挂载变化以及 AKB 端 ACL 的实时性仍需各自执行边界验证。本轮也未解决调用开始前已持有旧 spec 的全部缓存场景。不能据此宣称完整的用户授权交集或生产就绪。

## 隔离验证与最小解除条件

临时 SQLite、独立写连接及 httpx MockTransport 验证真实 REST 适配器编码/解码路径：合成凭据、KB 选择、上游 403、非来源所有者拒绝、来源名称/片段 ID/KB ref 保留，以及等待期间禁用、换 KB、换密钥、删除。禁止实际 socket connect/DNS。Agent 分支和多来源等待为显式测试替身，不是实际 AKB 验权。

尚无获授权的 AKB 测试 endpoint、对应可启动源码/镜像及测试身份配置，未尝试访问任何现有服务。实际联调最少需要：

1. 明确授权的隔离 AKB 实例与版本，允许的测试网络目标，使用合成文档。
2. AKB 管理方配置应用/Agent、公钥信任、policy/audience/resource 与资源授权；Octop 仅配置对应测试身份，不能代授 AKB 权限。
3. 两名独立测试用户及显式可信绑定，确认服务端强制内容 ACL（ENFORCE），同 KB 不同可见集合、撤权与缓存隔离均可验证。工作负载身份不能代替用户身份。
4. 明确的查询回执、片段来源和真实版本/追踪字段契约，验证后再决定如何进入运行与报告证据；没有上游字段时不得虚构版本或回执。

Docker client/server 29.9.2 可用；未启动 AKB 容器。bubblewrap 和 Chromium 已安装，但此前 UID 映射及浏览器沙箱限制仍未解除，本轮未重试或绕过。没有修改 AKB、网络/系统安全设置或安装依赖。

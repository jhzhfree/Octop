# 在线恢复安全拒绝门禁

2026-11-15，基线 `7233eaaa78a1fcb903c28ae21d5c24072abd2c0c`。
本阶段关闭未经安全协调的在线恢复入口；**没有完成安全恢复协议，仍是 1.0 阻断**。

> 后续状态：CLI、系统恢复与 SQLite 恢复原语也已[默认拒绝](offline-restore-gate.md)，
> 原非原子流水线已移除。下文保留本阶段分析，不再意味着 CLI 仍能恢复。

## 已核实的调用链和风险

原 HTTP `POST /api/admin/backup/files/{filename}/restore` 在取得进程内 BACKUP_LOCK 后，
线程调用 `restore_system_backup`，随后重载 Agent、IM 频道和 Cron，再写成功审计。
CLI `octop backup restore` 打开数据库后直接调用同一底层函数，只提示先停止服务，
没有可验证的跨进程停写屏障。

底层函数按顺序提取归档、保存可选聊天/账号、覆盖数据库、迁移、恢复配置文件、写回
账号/密钥、复制工作区和其他文件、恢复聊天。它不是跨资源原子事务，存在这些风险：

- 普通归档默认 `preserve_users=False`，恢复历史 users 和 secrets.jwt；历史密码、
  禁用状态、权限与签名密钥可能回退。当前撤销摘要并集无法弥补已丢失的历史，
  也不能证明所有旧令牌均无效。
- True/LightClaw 自动保留模式的 `_USER_COLUMNS` 不包括 permissions，也没有保留
  组织成员和各资源 ACL；JWT 写回在数据库替换后且不处于同一替换锁/事务。
- 不同 JWT 密钥、用户 ID 映射、被撤销成员、备份中已不存在的资源之间没有明示的
  安全恢复策略。简单多复制一个字段可能制造错误授权或外键关系，不能视为修复。
- BACKUP_LOCK 和 SqlitePool 的锁只协调各自进程/对象；不限制独立进程、另一连接或
  外部写入者。文件复制失败、掉电、数据库替换后失败也没有完整自动回滚。
- PostgreSQL 走 pg_restore，不能据 SQLite 测试认为它已安全或原子。

## 本阶段实际行为

保留旧 HTTP 路由和 backup 权限要求。身份/权限检查之后，一律返回 409
`BACKUP_ONLINE_RESTORE_UNAVAILABLE`，在读取归档、数据库替换、文件复制、运行时重载
以及成功审计之前停止。SQLite/PG、管理员/授权用户、旧客户端、配置参数开关均不能
绕过；不提供 force、maintenance 自报标记或 preserve_users 参数作为安全证明。
旧格式与迁移归档也不进入解析/恢复，因而没有静默改变其原有导入数据语义。
门禁只作用于已升级的服务进程，不能取消旧进程已经入场的恢复，也不能保护仍运行
旧代码的工作进程；混合版本部署不得被视为已经关闭在线恢复。

桌面表格、移动卡片和恢复确认按钮均禁用，并显示中英文原因。创建、自动备份、上传、
列表、下载、导出、删除维持现有行为。拒绝后当前账号、权限、密钥与工作区保持原状，
用户仍可登录、下载归档进行后续受控恢复准备。**当前没有可用的在线恢复流程。**

这是安全拒绝，不是锁或停写屏障。CLI 与导出的底层恢复函数在本阶段没有改变数据
语义，仍存在上述风险；不得将它们当作在线拒绝后的安全绕行方案，也不能声称已有
完整产品范围的默认安全恢复。需要后续独立收口这些入口，才能关闭整个恢复阻断。

## 下一阶段恢复设计要求（尚未实现）

1. 明示策略和来源：同实例恢复、全新环境灾难恢复、外部迁移分别处理；默认不把历史
   身份/授权自动重新激活。同实例必须保留当前完整安全状态或拒绝无法映射的数据，
   覆盖用户权限、禁用状态、组织成员、资源所有权/ACL和关联身份，不能仅复制已知几个字段。
   外部迁移和历史格式缺失安全元数据时拒绝隐式降级，不猜测拥有者映射。
2. 实际维护协议：所有运行进程、调度器、写入端和认证入口必须进入可验证维护状态，
   新进程启动也必须遵守维护标记。旧进程/独立写入者无法确认静止时拒绝应用；
   不能以 HTTP 参数、管理员身份、文件存在或进程内锁代替跨进程协调。
3. 私有准备副本：先迁移、检查完整性/引用和完整授权映射；在副本中一次完成身份、
   ACL、撤销策略与新密钥。默认不复用归档 JWT 密钥；强制重新登录的操作性须通过
   独立、受控的恢复管理员流程验证，避免恢复后无法管理或凭历史密码重入。
4. 原子发布和故障协议：定义数据库、配置、工作区的恢复代际与提交边界，保留可验证
   的回滚材料；启动时遇到未完成恢复必须安全关闭，不能启动频道或定时任务。
   数据库替换、文件写入、身份准备、重启各节点都要故障注入，不能只测正常路径。
5. 测试矩阵：不同当前/归档 JWT、历史管理员降权、组织成员撤权/删除、权限收紧、
   用户 ID 冲突、老 schema/格式、旧客户端、多个进程/连接、新进程竞争、磁盘失败、
   崩溃后启动、恢复管理员登录和正常业务回归。PG 单独设计和实测。

这些要求是后续实现/验收门槛，不是本阶段已具备的能力或生产操作授权。

# 单会话退出撤销（schema 038）

## 行为与部署

所有本地/LDAP 登录、OIDC/OAuth 兑换、邀请兑换、初始化管理员、Bridge 内部签发均复用 JWT 签发器；新令牌含随机 `sid`，滑动续期保留同一 `sid`。退出仅撤销这个登录家族，不退出同用户其他浏览器或独立服务登录。HTTP 与 WebSocket **新连接**的统一鉴权会读取数据库，撤销提交后拒绝该家族的原令牌及其所有续期令牌。退出响应不携带续期令牌。

038 为 SQLite/PostgreSQL 增加 `auth_session_revocations` 表，使用现有迁移启动流程。只保存 subject+sid 的 SHA-256 摘要及撤销时间，不保存 JWT。多 worker 必须共享同一控制面数据库，不能使用各自 SQLite 副本。SQLite 多连接与重开验证已覆盖；PostgreSQL 迁移及 SQL 采用现有兼容池，未在真实 PostgreSQL 服务验证。

数据库读写故障返回 503（不假报退出成功、不放行新鉴权）；刷新检查失败不发新令牌。并发请求若在退出前已经通过校验，其稍后签发的令牌仍继承原 sid，后续使用会被拒绝，无法复活会话。

## 兼容性与边界

- 无 sid 的升级前 JWT 使用该令牌的稳定 SHA-256 派生家族；升级后的续期继承它，退出同时撤销原令牌与升级后续期。**升级前已经各自续期生成的多个无 sid 令牌无法恢复共同家族**，不能声称同时撤销；要求完整旧会话失效的部署应按既有运维流程统一轮换 JWT secret，用户重新登录，并重启全部旧 worker。
- 不取消退出前已经获准的请求，不强制断开已建立 WebSocket/流连接。终端和长期流的主动关闭需要另行会话注册/断连设计。客户端应在退出时关闭自己的连接。
- 不做“全设备退出”、密码变更撤销全部会话或服务凭据生命周期改造。
- 滑动会话没有固定最大寿命，撤销记录不得按某个旧 JWT 的 exp 删除，否则仍可存活的续期子令牌会复活。当前不清理 tombstone，容量随退出次数增长。
- 不支持新旧服务版本混跑的强撤销保证；旧 worker 不读此表。上线需统一替换 worker，回退到旧版本会失去撤销保护。数据库备份恢复须保留撤销表，恢复旧备份可能复活恢复点后退出的会话。

## 离线验收

`tests/integration/test_logout_revocation.py` 使用临时目录、ASGITransport 和本地数据库：原令牌/滑动后代/并发晚签令牌拒绝、独立登录保留、旧JWT兼容、DB故障关闭、多连接/重开持久化、无原token落库、异常sid拒绝、037→038迁移保留数据。执行时额外封禁 socket 出站，不调用真实模型、连接器、外部身份平台或生产数据。

# 服务端续期请求限流

2026-11-15，开发基线 `83027c979644044e19cffb7df5b31ffe190046fd`。

`POST /auth/renew` 原先只有前端活动节流，自定义客户端可以持续调用。本阶段增加
数据库共享的账号级准入：同一已认证账号在同一 UTC 整数秒内最多放行 10 次续期
请求，包括无需签发新令牌的 204 请求。限流发生在签发之前；使用真实认证后的
user id，不相信请求体、IP 转发头、活动声明或客户端上报的会话身份。

SQLite/PostgreSQL 新增配对迁移 043 `auth_renew_buckets`。旧库 042 已有部署记录，
所以新增编号，不能把表折回已执行的迁移。每账号最多一行，删除用户级联删除；
不存原始 JWT、sid 或凭据。持久化用户缺失/禁用时拒绝。数据库事务内条件 UPSERT
原子计数，多个新版本工作进程共享同一数据库时使用同一额度；换令牌家族、重开
数据库连接或改变代理头不重置额度。数据库不可用时返回 503，不降级为无限续期。

超限返回本地化 `RATE_LIMITED` 错误、HTTP 429、整数 `Retry-After` 和 no-store，
不返回新令牌、不撤销会话，不影响普通已授权读取。计数已提交后签发失败仍消耗
本秒额度，这是保守的请求准入而不是成功签发计数。

前端只在当前令牌仍匹配、页面可见且活动续期仍启用时接受 429 的正整数等待秒数。
从收到响应开始等待，最大采用 3600 秒；之后仍须新的可信用户活动才发起请求，
没有加入定时续期、后台心跳或自动请求重放。无效等待值沿用已有节流。CORS 仅在
原有允许来源配置下额外暴露 Retry-After，不扩大允许来源。

## 实际边界

- 这是固定秒窗口，跨秒边界附近可能合计放行 20 次，不是滚动秒窗口或令牌桶。
- 账号共享额度意味着某个已持有该账号令牌的客户端可挤占该账号额度。其他账号
  独立计数；不是全站负载防护，也不限制登录、无效令牌、鉴权前开销或数据库争用。
- 时间源为应用服务器 UTC 秒。向后跳时不提前重置已存额度，可能延长等待；多机
  时钟偏差会影响窗口，必须由部署验收验证。没有修改系统时间或网络设置。
- 只有运行本版本且使用同一数据库的入口受约束，旧工作进程或不同数据库不共享
  此契约。本轮真实多进程验证仅为本机临时 SQLite；PG 只交付配对迁移，未真实联调。
- 不是空闲/绝对会话期限，也不是用户真实活动证明；持令牌客户端仍可在限额内
  长期显式续期。该默认生命周期策略尚未确认，不能因此宣称认证已达到 1.0。

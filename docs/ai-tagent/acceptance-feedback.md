# 巡检交付的人工验收反馈闭环

2026-11-16，开发基线 `f5efc2db4d7a630f643d624b79a60c9c250af2fb`。

## 用户问题与本轮行为

原流程可将交付标记为“要求修改”，但没有保存修改意见，也没有供申请人独立读取
反馈的入口，申请人无法从同一运行知道要改什么。

本轮在验收表单增加最多 2000 字符的意见。界面要求“要求修改”先填写非空说明，
再确认不可覆盖的决定；“通过”可选填说明。修改文字会取消已选确认状态，避免
未确认的文字被提交。服务端去除首尾空白，与决定、证据哈希、快照哈希、验收人
同事务保存；完全相同的重试幂等，改变意见或决定返回冲突。审计记录意见 SHA-256，
不把原文复制进通用审计 payload。

申请人在组织运行待办中打开同一个 run，点击“查看验收反馈”即可读到决定、验收人
和意见，无需获得验收写权限；没有决定时明确显示尚无验收。内容按普通文本显示，
不会执行其中 HTML。切换账号/组织/run、关闭或敏感权限状态失效会销毁旧内容及
迟到响应。读取失败清除旧内容，不自动重试写操作。

## 可复现操作

在隔离开发实例使用合成账号与经授权的测试 HTTP 来源：

1. 申请人与独立验收人加入同一组织，验收人为 manager；建立岗位和已绑定 Agent
   的数字员工，启用目标并将方案设为 ready，创建对应场景。
2. 在企业助手配置该申请人拥有的 HTTP 巡检连接与任务，启用巡检/报告并设置允许
   来源；申请场景运行时选择“单次 HTTP 巡检”，选任务并明确同意共享。
3. 独立账号审批运行，待单次执行生成本地报告后打开验收摘要。填入例如“请补充
   超时端点的重试结果”，选“要求修改”，再次确认。
4. 申请人打开组织运行待办，选择“要求修改”并刷新，点击该 run，再点“查看验收
   反馈”。读到上述意见、原验收人及决定；报告仍来自同一个 run。
5. 如需补充工作，人工调整后另行申请新运行。本轮不自动重跑，不覆盖原决定，不
   自动改变目标终态；“通过”和“要求修改”两条分支均保持目标 active。

可在仓库复现不出网的完整服务端流程：

```bash
UV_CACHE_DIR=/tmp/octop-uv-cache UV_OFFLINE=1 uv run pytest \
  tests/integration/test_fresh_install_inspection_delivery.py -q
```

该测试从空 SQLite 的初始化 HTTP 接口开始，创建组织、岗位、Agent、数字员工、
目标、方案、场景与巡检任务，再走申请→独立审批→执行→本地报告→人工验收→申请人
读回意见。HTTP 巡检响应是合成替身，socket/DNS 外连被测试禁止，模型 stream 调用
会立即失败；真实数据库、领域服务、ASGI 路由和持久化均参与。它不是浏览器端到端
或真实服务器巡检验收。Agent 建档仍沿用现有模型配置要求，测试只注册未调用的
合成 provider；不代表真实模型已配置或联调。

## 权限、升级与兼容

- 新增 `GET /organizations/{organization_id}/scene-runs/{run_id}/acceptance`，返回
  当前记录或 null，no-store。沿用运行证据可读范围，并重新核对数据库中账号启用
  状态和组织成员关系；只允许当前管理员、该运行申请人或审批人。其他 manager
  不能因知道 run ID 而读取意见，跨组织不得访问；读取不提供验收写权限。
- `POST .../acceptance` 新增可选 `review_note`。SQLite/PG 配对迁移 044 添加
  非空默认空字符串列与长度约束；历史决定保持不变，不补写推测的修改理由。
- 旧客户端可以省略意见，仍按原行为提交；因此 API 不把意见非空作为所有客户端
  的硬性要求。界面明确标示历史/空意见为“未记录”，不宣称所有修改决定都有说明。
  重试已有带意见的决定必须带相同的规范化意见，不能用旧客户端空字段覆盖。
- PG 迁移仅静态配对检查，未在真实 PostgreSQL 执行。意见由已认证账号提交，
  不证明真人本人点击；不是模型生成内容，也不作为可执行指令发送给任何工具。

## 验证与仍缺能力

后端验证意见幂等/不可覆盖、并发只提交一次、事务审计、长度/非法字符拒绝、旧记录
迁移、申请人读取、无关用户/撤销成员拒绝，以及两条空库巡检验收分支。迁移后既有
恢复镜像/隔离回归也运行，恢复激活仍关闭。

首轮新增空库验证 2 项失败，原因是测试最后使用了不存在的单目标 GET 路由；改用
既有目标列表接口后通过，未新增不必要的产品接口。

最终后端定向回归 150 项通过：acceptance 领域/API、空库巡检两分支及 recovery_image；
2 条既有 ldap3/pyasn1 弃用警告。前端 5 文件 37 项通过，含敏感权限失效清屏。
`UV_CACHE_DIR=/tmp/octop-uv-cache UV_OFFLINE=1 make lint-all typecheck-all` 与
`npm run build` 均通过；mypy 665 文件、ESLint 69 warnings / 0 errors，保留既有
构建体积和 jsdom 样式模拟提示。OpenAPI 核对新增 GET 摘要及意见长度/默认值声明。

真实 HTTP 端点连通和允许名单需在用户授权环境独立验收；模型、AKB 知识库、堡垒机
均未参与本次单次 HTTP 流程。Mattermost 仍只有本地预览/审批且真实发送关闭。
不将该测试视为自主规划、多轮自动修复、周期调度或 1.0 完整发布验收。未运行全量
make all、受限遥测、生产部署或真实外发。

后续阶段提供[巡检修订向导](inspection-revision.md)，具体入口和当前验证边界见该记录；
上述结果保留为本阶段历史证据。
